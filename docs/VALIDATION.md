브라우저 검증 사진은 테스트용 라이선스 이미지이며 실제 사용자 여행 데이터가 아니다. 테스트는 별도 자동화 브라우저 세션에서 실행했다.

발견·수정: 누락된 favicon 추가, Spring JDBC 결과 조회 메서드 수정, React 개발 갱신 시 중복 root 경고를 방지하도록 부트스트랩과 App 컴포넌트 분리.

검증 범위 밖: Docker compose의 PostgreSQL 17 직접 실행(Docker 엔진 미실행), 대량 사진 부하, S3, 썸네일 처리, 이메일 복구, 실제 모바일 장치. 공식 17용 schema는 18.4에서 실행 검증했으며 17 환경의 검증은 별도 필요하다.

API 재검증: 개발용 백엔드가 실행된 상태에서 `node scripts/smoke-api.mjs` 및 `node scripts/smoke-account.mjs`. 독립 테스트 사용자와 사진/기록을 생성하므로 운영 DB에서 실행하지 않는다. UI 테스트에서 만든 일회용 계정과 사진이 개발용 통합 DB에 남아 있다.

스크린샷은 `output/playwright`에 저장되며 버전 관리에서 제외한다.

2026-10-07 추가 확인: 로컬 PostgreSQL 18.4 개발 클러스터(`127.0.0.1:55433`)에 Flyway V1·V2·V3가 적용되었고, Spring Boot(`8080`) 및 미리보기(`5175`)를 연결했다. 미리보기의 `/api/regions` 응답은 200이며 17개 지역이 반환된다. Docker Desktop 엔진은 실행 중이지 않아 Docker Compose의 PostgreSQL 17은 이번 확인에 사용하지 않았다. 이 실행 상태는 컴퓨터/프로세스 재시작 후 유지된다고 보장하지 않는다.

장소별 사진 추가 검증: Flyway V3를 기존 여행 기록이 있는 개발 DB에 적용했다. 체험 모드 브라우저에서 DAY 1에 두 장소를 만들고 각각 다른 사진을 선택해 저장했다. 상세 화면과 새로고침 후 재조회에서 두 사진이 각 장소 오른쪽에 유지됐고, 기록 수정 후에도 보존됐다. API 통합 검증에서는 장소 사진 저장·조회, 수정 시 사진 유지, 명시적 제거, 계정 삭제 시 연결 사진 정리를 확인했다. React 빌드와 Spring Boot 테스트도 통과했다.

2026-10-13 다중 지역 여행 검증: 체험 모드 390×844 브라우저에서 `강릉시 → 속초시 → 양양군`을 한 여행으로 저장했다. 강원 지도에서 세 지역이 모두 방문으로 표시되고 각 지역 목록에서 같은 기록을 열 수 있으며, 상세·수정 화면의 순서 유지와 MY의 지역 +3/여행 +1/일수 1회 합산을 확인했다. 화면 전환 시 남던 스크롤 위치를 수정 후 재검증했고 콘솔 오류는 0건이었다. React 빌드·테스트와 Spring Boot 테스트를 통과했다. PostgreSQL 18.4 격리 개발 DB에 Flyway V4·V5를 적용하고, 다중 지역 생성·조회·수정·통계·삭제 및 기존 소유권·사진·멱등성 시나리오를 포함한 API 스모크도 통과했다.
