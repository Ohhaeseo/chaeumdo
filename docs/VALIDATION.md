React 빌드·테스트와 Spring Boot 테스트를 통과했다. Docker 엔진이 꺼져 있어 변경한 `nginx.conf`(전달 프로토콜, 요청 속도 제한)는 실제 Nginx로 실행하지 못했다.

2026-10-18 오류 메시지·캐시·HTTPS 구성: 의도된 서버 오류가 `{status, message}` JSON으로 내려오고, 로그인 실패 시 앱이 서버 문구("아이디 또는 비밀번호를 확인해 주세요.")를 그대로 보여 주는 것을 브라우저에서 확인했다. 입력 검증 실패는 내부 정보 없이 상태 코드만 돌려준다. DB에서 세션 토큰을 바꿔 다른 기기 로그인을 흉내 낸 뒤 기록을 저장하면, 업로드가 401을 받고 앱이 로그인 화면으로 돌아갔다. 임시 PostgreSQL 18 클러스터에서 `smoke-api.mjs`(오류 메시지 본문 포함)와 `smoke-account.mjs`를 통과했고, React 빌드·테스트와 Spring Boot 테스트도 통과했다. Nginx 보안 헤더를 `nginx-security-headers.conf`로 분리해 캐시 헤더를 지정한 위치에도 포함했고, `index.html`은 `no-cache`, 글꼴은 30일 캐시로 설정했다. 운영 compose에는 자동 HTTPS용 Caddy를 추가했다. Docker 엔진이 꺼져 있어 Nginx·Caddy 설정과 compose 구성은 실제 컨테이너로 실행하지 못했다.

2026-10-18 운영 컨테이너 검증(Docker Desktop 29.8, Compose 5.5): `compose.production.yaml`을 별도 프로젝트 이름(`chaeummdo-verify`)으로 빌드·기동했다. Caddy는 루프백 포트 8088/8443으로만 열었고 `DOMAIN=localhost`라 Caddy 내부 인증서를 썼다. `DOMAIN`이 없으면 compose가 시작을 거부하고, `caddy validate`와 `nginx -t`도 통과했다. Caddy를 거쳐 `index.html`·SPA 경로(`no-cache`), 해시 자산(`immutable`), 지도 경계(1시간), 글꼴(30일, `font/otf`), favicon 모두에 CSP·X-Frame-Options·nosniff·Referrer-Policy·Permissions-Policy·HSTS가 붙었다. HTTP는 308로 HTTPS로 이동했다. 이 과정에서 Caddy가 붙이는 `Via` 헤더 때문에 Nginx gzip이 전부 꺼진 것을 발견해 `gzip_proxied any`로 고쳤다(JS 276KB→57KB, 지도 경계 662KB→247KB, 글꼴 730KB→348KB). PostgreSQL 17 컨테이너를 포함한 전체 경로에서 `smoke-api.mjs`가 통과했고, 가입 쿠키에 `Secure`가 붙었다. 17MB 업로드는 Nginx 413, 이미지가 아닌 파일은 서버 문구가 담긴 400을 받았다. 동시 요청 시험에서 로그인 POST 20건 중 9건, 사진 업로드 POST 60건 중 12건이 429를 받았고, `GET /api/auth/me`·사진 조회는 제한되지 않았다.
