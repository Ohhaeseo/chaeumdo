# 국내 여행 지도 앱 PRD

> **문서 목적:** 1주일 내 구현 가능한 MVP의 제품 범위와 동작 기준을 정의한다.
> **제품 한 줄 설명:** 여행 기록을 남길수록 내 사진으로 채워지는 대한민국 여행 지도.

## 1. 문제

여행자는 여러 지역을 방문하지만 여행 사진과 일정이 갤러리, 메모, SNS 등에 흩어져 지난 여행을 한눈에 돌아보기 어렵다. 방문한 지역과 아직 가보지 않은 지역을 확인하고, 다음 여행지를 떠올리는 경험도 분리되어 있다.

이 앱은 여행 기록을 지도에 연결해 **어디를 다녀왔는지 시각적으로 모아 보고, 기록을 다시 열어 추억을 확인하며, 아직 방문하지 않은 추천 지역을 발견**하도록 돕는다.

### 해결하려는 사용자 문제

- 내가 국내 어느 지역을 여행했는지 빠르게 돌아보고 싶다.
- 여행 사진과 날짜, 동행인, 일정을 한 기록으로 정리하고 싶다.
- 아직 방문하지 않은 지역 중 다음 여행 후보를 지도에서 발견하고 싶다.

## 2. 타깃

### 핵심 타깃

- 국내 여행을 다녀온 뒤 사진과 간단한 일정 기록을 남기고 싶은 사람
- 방문한 지역을 시각적으로 모아 보는 것을 좋아하는 사람
- 다음 국내 여행지를 가볍게 탐색하고 싶은 사람

### MVP 사용자 가정

- 사용자는 여행이 끝난 뒤 지역 단위로 기록을 직접 입력한다.
- 한 여행 기록은 이동 순서대로 하나 이상의 시·군·구에 연결되며 첫 지역을 대표 지역으로 사용한다.
- 사용자는 지도에서 방문 현황을 확인하고, 지역을 눌러 과거 기록을 다시 연다.

## 3. 서비스 컨셉 및 가치 제안

### 서비스 컨셉

**대한민국 지도를 나의 여행 사진으로 채워 가는 기록 앱.**

### 핵심 가치

1. **한눈에 보는 여행 이력:** 지도에서 방문 지역과 미방문 지역을 구분한다.
2. **사진으로 채워지는 지도:** 해당 지역의 여행 기록에 연결된 대표 사진을 방문 지역의 시각 요소로 사용한다.
3. **가벼운 다음 여행 발견:** 미방문 추천 지역을 별도 색으로 표시하고, 선택하면 “다음 여행지로 어때요?” 화면을 보여준다.
4. **간편한 회고:** 지역을 선택해 저장된 여행 기록과 상세 내용을 다시 확인한다.

추천은 MVP에서 서비스가 미리 지정한 지역을 표시하는 방식이다. 사용자의 취향을 분석하거나 개인별 추천 순위를 계산하지 않는다.

## 4. 최종 User Flow

### 주요 흐름

```text
앱 실행
  ↓
지도 탭: 대한민국 여행 지도
  ├─ 방문 지역 선택 → 해당 지역 여행 기록 목록 → 기록 상세
  ├─ 미방문 추천 지역 선택 → “다음 여행지로 어때요?” 화면
  └─ 여행 기록 추가
       ↓
     여행 지역을 순서대로 선택
       ↓
     대표 사진·여행 날짜·동행인 입력
       ↓
     날짜별 방문 장소 입력
       ↓
     저장
       ↓
     지도 복귀: 해당 지역이 방문 지역으로 표시되고 대표 사진 반영

MY 탭 → 방문 지역 수·총 여행 횟수·총 여행 일수 확인
```

### 신규 여행 기록 흐름

1. 지도 화면의 `+ 여행 기록`을 누른다.
2. 시·도를 선택한 뒤 여행한 시·군·구를 이동 순서대로 최대 10곳까지 추가한다.
3. 대표 사진을 선택하거나 촬영한다.
4. 시작일과 종료일을 입력한다.
5. 동행인을 입력한다. (선택 사항)
6. 여행 일수에 맞춰 DAY별 방문 장소를 입력한다. 장소는 자유 입력하거나 검색 결과를 선택해 지도 위치를 연결한다.
7. 저장하면 기록 상세 또는 지도 화면으로 이동하고, 지도에 방문 상태와 사진을 반영한다.

### 기존 기록 다시 보기 흐름

지도에서 방문 지역을 선택하면 해당 지역의 여행 기록 목록을 연다. 기록을 선택하면 대표 사진, 날짜, 기간, 동행인, DAY별 장소를 확인한다. 같은 지역에 기록이 여러 개면 목록에 각각 표시한다.

## 5. MVP 범위

### Must Have

| 기능 | 요구사항 및 완료 기준 |
|---|---|
| 대한민국 지도 홈 | 앱 진입 시 전국 지도를 표시한다. 시·도를 선택하면 확대 지도에서 시·군·구를 선택할 수 있다. |
| 방문 상태 표시 | 여행 기록이 하나 이상 있는 지역은 방문 지역으로 표시하고, 기록이 없는 지역은 미방문 상태로 표시한다. |
| 대표 사진으로 지도 채우기 | 여행 기록의 대표 사진을 해당 방문 지역 표시의 사진 콘텐츠로 사용한다. 한 지역에 여러 기록이 있으면 지역 선택 후 기록 목록에서 각 사진을 확인할 수 있다. 지도 안에 사진을 합성하는 방식은 사용 UI/지도 구현에 맞춰 단순한 타일·썸네일 표현으로 구현한다. |
| 추천 미방문 지역 강조 | 미리 지정한 추천 지역 중 아직 기록이 없는 지역만 별도 강조 색상으로 표시한다. 추천 설정은 정적 목록으로 관리한다. |
| 추천 지역 안내 | 추천 지역 선택 시 “다음 여행지로 어때요?” 문구와 간단한 지역 안내를 표시한다. 기록이 생긴 지역은 추천 상태보다 방문 상태를 우선한다. |
| 여행 기록 생성 | 하나 이상의 여행 지역과 순서, 대표 사진, 시작일·종료일, 선택 동행인, DAY별 텍스트 장소를 기록한다. 필수 입력은 지역, 사진, 날짜로 한다. |
| 장소 검색·지도 핀 | 사용자가 명시적으로 장소를 검색해 결과를 선택하면 이름·주소·좌표를 저장하고 상세 화면 지도와 DAY 목록에 같은 번호 핀을 표시한다. 검색 실패 시 자유 입력은 계속 사용할 수 있다. |
| 여행 기간 자동 계산 | 입력한 날짜를 포함 일수로 계산한다. 예: 9월 10일~12일은 3일 여행(2박 3일)로 표시한다. 시작일은 종료일보다 늦을 수 없다. |
| 기록 목록·상세 | 방문 지역에서 해당 지역 기록을 다시 열어 목록과 상세 정보를 확인한다. |
| 여행 기록 삭제 | 상세 화면에서 재확인 후 본인의 기록을 삭제한다. 삭제 후 지도·지역 목록·MY 통계를 즉시 다시 계산한다. |
| MY 통계 | 방문 시·군·구 수, 총 여행 횟수·일수, 전국 채움률, 올해 새로 방문한 지역, 최다 방문 지역과 시·도별 채움률을 표시한다. |
| 하단 탭 | `지도`, `MY` 두 탭만 제공한다. 여행 기록 생성은 지도 화면의 추가 동작으로 시작한다. |
| 데이터 유지 | 앱을 다시 열어도 사용자의 기록과 사진 참조가 유지된다. 구현 환경에 맞는 로컬 저장 또는 간단한 백엔드를 사용한다. |

### Out of Scope

- AI 기반 추천, 개인화 추천, 취향 분석 및 추천 순위화
- GPS 위치 추적, 자동 방문 인증, 이동 경로 기록
- 장소 자동완성, 장소 상세 정보·영업시간 연동
- 소셜 피드, 친구·팔로우, 댓글, 좋아요, 공유 기능
- 배지, 미션, 랭킹, 게임화 요소
- DAY별 지도 경로, 교통·숙박·예약 관리
- 사진 자동 분류, 위치정보(EXIF) 분석, 앨범 전체 가져오기
- 고급 통계, 그래프, 연도별 분석 및 데이터 내보내기
- 다국어 및 해외 지도
- 추천 지역 관리용 운영자 도구

### 1주 MVP 우선순위

1. 지도에서 방문/미방문/추천 상태를 구분한다.
2. 지역별 여행 기록을 추가하고 저장한다.
3. 저장 기록을 지도와 지역 상세에서 다시 확인한다.
4. MY의 세 가지 통계를 계산해 표시한다.
5. 남은 시간에 화면 다듬기와 오류 상태를 보완한다.

## 6. 정보 구조 (IA)

```text
앱
├─ 지도 탭 (기본 진입 화면)
│  ├─ 대한민국 여행 지도
│  │  ├─ 방문 지역
│  │  │  └─ 지역별 여행 기록 목록
│  │  │     └─ 여행 기록 상세
│  │  ├─ 미방문 지역
│  │  └─ 미방문 추천 지역
│  │     └─ 다음 여행지 안내
│  └─ 여행 기록 추가
│     ├─ 지역 선택
│     ├─ 대표 사진 선택
│     ├─ 날짜 및 동행인 입력
│     ├─ DAY별 장소 입력
│     └─ 저장 완료
└─ MY 탭
   ├─ 방문 지역 수
   ├─ 총 여행 횟수
   └─ 총 여행 일수
```

**탐색 원칙:** 여행 기록은 별도 하단 탭으로 두지 않는다. 지도에서 지역을 선택하면 기록에 접근하고, 지도에서 새 기록을 추가한다.

## 7. 핵심 화면 및 동작 규칙

### 지도 홈

- 방문 지역: 사용자의 여행 사진이 보이는 스타일로 표시한다.
- 미방문 일반 지역: 채도가 낮은 단색 또는 흑백 스타일로 표시한다.
- 미방문 추천 지역: 일반 미방문 지역과 구분되는 강조 색을 사용한다.
- 지역 상태가 겹칠 때 우선순위는 **방문 > 추천 미방문 > 일반 미방문**이다.
- 지도 범례 또는 짧은 안내로 각 스타일의 의미를 알려준다.
- 지도에서 지역을 선택하면 해당 지역의 상태에 맞는 화면을 연다.

### 추천 지역 안내

- 제목/핵심 문구: **“다음 여행지로 어때요?”**
- 지역명과 짧은 소개를 표시한다.
- MVP에서는 미리 작성한 정적 소개를 사용한다.
- 추천 화면은 탐색용이다. 여기서 여행 기록을 시작할 수 있는 버튼을 둘 경우 선택한 지역을 기록 생성 폼에 미리 반영한다.

### 여행 기록 폼

| 항목 | 입력 규칙 |
|---|---|
| 지역 | 필수, 시·도 선택 후 한 개의 시·군·구 선택 |
| 대표 사진 | 필수, 한 장 |
| 시작일·종료일 | 필수, 종료일은 시작일과 같거나 이후 |
| 여행 기간 | 날짜 입력에 따라 자동 계산, 직접 편집 불가 |
| 동행인 | 선택, 자유 텍스트 |
| DAY별 방문 장소 | 자유 텍스트 목록. 선택적으로 장소 검색 결과의 주소·좌표를 연결 |

- 날짜 범위가 변경되면 DAY 입력 칸 수도 함께 갱신한다.
- 장소 입력은 선택 사항이며, 장소가 비어 있어도 기록을 저장할 수 있다.
- 저장 중 중복 제출을 방지하고, 저장 성공 여부를 사용자에게 알린다.

### 기록 상세와 통계

- 상세 화면에는 지역, 대표 사진, 여행 날짜, 자동 계산 기간, 동행인, DAY별 장소를 표시하고 좌표가 있는 장소는 번호 핀 지도에 함께 표시한다.
- 방문 지역 수는 고유 지역 기준으로 센다.
- 총 여행 일수는 각 여행 기록의 시작일과 종료일을 포함한 일수 합계다. 겹치는 날짜의 여행 기록도 각각의 기록 기간을 합산한다.

## 8. MVP 데이터 항목

| 객체 | 주요 필드 |
|---|---|
| 지역 | 지역 ID, 지역명, 지도 표시용 도형/키, 추천 여부, 추천 소개 |
| 여행 기록 | 기록 ID, 지역 ID, 대표 사진 참조, 시작일, 종료일, 동행인, 생성 시각 |
| 여행 일자 | 기록 ID, DAY 번호, 방문 장소명, 선택적 사진·주소·좌표·출처 식별자 목록 |

방문 여부는 지역별 별도 입력값이 아니라 해당 지역에 저장된 여행 기록 존재 여부로 판단한다. 사진 원본 저장 방식은 플랫폼의 사진 선택 기능과 저장 환경에 맞춰 결정한다.

## 9. 성공 기준

MVP 구현 완료 시 다음을 확인할 수 있어야 한다.

- 사용자가 지도에서 방문 지역, 일반 미방문 지역, 추천 미방문 지역을 구분할 수 있다.
- 새 기록을 저장하면 선택한 지역이 방문 지역으로 바뀌고 대표 사진이 반영된다.
- 지역에서 이전 기록을 다시 열어 상세 정보를 볼 수 있다.
- MY 통계가 저장된 기록과 일치한다.
- 하단 내비게이션은 지도와 MY 두 항목으로 구성된다.

## 10. 주요 가정 및 결정 사항

- 전국 지도는 시·도 단위로 시작하고, 여행 기록은 하위 시·군·구 단위로 저장한다.
- 추천 지역은 초기 버전에서 정적 목록이며, 기록되지 않은 추천 지역만 강조한다.
- 한 기록은 하나 이상의 지역에 연결되며 첫 지역을 대표 지역으로 사용한다. 연결된 모든 지역에서 같은 기록을 열고 방문 통계에 반영한다.
- 여행 일수 계산은 시작일과 종료일을 모두 포함한다.
- 사진은 사용자가 직접 한 장 선택한다. 지도에서 사진을 지역 모양에 맞춰 자르는 연출은 지도 라이브러리와 개발 여건에 따라 단순 표현부터 구현한다.
- 사용자 계정, 동기화, 백업 요구가 확정되지 않았으므로 1주 MVP에서는 최소 데이터 저장 경로를 우선한다.
